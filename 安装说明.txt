知乎阅读 · Kindle 原生客户端  安装说明
版本 1.3.2
========================================

这是一个独立运行在越狱 Kindle 上的知乎客户端，
不是 KOReader 的插件，运行时不依赖电脑、手机或任何服务器。


一、准备
--------
1. Kindle 已越狱，并已安装 KUAL（越狱方法见 kindlemodding.org）
2. 电脑上解压本压缩包


二、安装（三步）
----------------
1. 用 USB 线连电脑，把压缩包里的整个目录

       extensions/zhihureader

   复制到 Kindle 的

       /mnt/us/extensions/

   复制完成后，路径应该是：
       /mnt/us/extensions/zhihureader/config.xml
       /mnt/us/extensions/zhihureader/menu.json
       /mnt/us/extensions/zhihureader/app/zhihu
       /mnt/us/extensions/zhihureader/bin/start.sh

2. 安全弹出 USB，Kindle 上打开 KUAL，
   找到「知乎阅读」→「1. 启动与安装」→「安装 / 更新程序」。
   屏幕会显示 "installed ... size=..."。

3. KUAL →「知乎阅读」→ 第一项就是「知乎阅读」，点一下即启动。
   （安装/更新、日志、自检等都在第二项「诊断和排障」里。）

   ※ 从 1.0.0 升级的话，第 2 步必须先做一遍，
     否则仍在跑旧程序。


三、怎么用
----------
· 首页（10 项）：
    热榜 / 推荐 / 私信 / 账号·登录 / 搜索 /
    我的收藏 / 阅读历史 / 设置 / 关于 / 退出
· 列表页：点条目打开；右下角「返回」退出；「上一页 / 下一页」整页翻
    （第 2 页首行就是第 14 条）；推荐列表还有「刷新」
· 阅读页：
    - 点屏幕左侧  -> 上一页
    - 点右侧正文  -> 下一页（整页翻，和看电子书一样）
    - 右下角「返回」-> 回列表（页脚这一条不再触发翻页）
    - 有翻页键的机型，按键也能翻；左右滑动也能翻
    - 底部显示页码和进度
    - 「显示图片」有三档（设置里点一下换一档）：
        关闭     -> 只留一行「[图片]」
        点按加载 -> 图片位置写着「点按加载此图」，点哪张下哪张
        自动加载 -> 文字先出来，占位框写「图片加载中… n/N」，
                    后台从第一张开始补，补上就刷新当前页
· 任何次级页面（列表/阅读/设置/账号/二维码/私信/关于）右下角
  都有同一个「返回」，位置和样子都一样
· 设置里可以改（点一下换一档）：
    正文字号 / 翻页刷屏·主界面刷屏（各四档）/
    界面旋转 / 显示图片（关闭／点按加载／自动加载）/
    页边距 / 推荐条数（6／12／18）/ 系统状态栏（隐藏／显示）/
    重新排版 / 清空缓存（含图片缓存）
· 「系统状态栏」选隐藏（默认）时，程序会接管系统界面，
  Kindle 顶栏的时间/网络/电量彻底不再出现——需重启程序生效；
  选显示则与系统共存，顶栏偶尔可见。


三之二、登录（推荐、私信、收藏夹需要）
--------------------------------------
1) 二维码扫码（推荐，纯 Kindle 上完成）
   首页 →「账号 / 登录」→「二维码扫码登录」
   屏幕出现二维码后，用手机知乎 App 扫码，在手机上点「确认登录」。
   每 2 秒自动查一次状态，期间随时可点屏幕返回，不会卡住。
   成功后账号页会显示用户名。

2) 导入 Cookie（扫码被风控时的兜底）
   浏览器登录知乎 → F12 → Network → 任意请求 →
   Request Headers → 复制 Cookie 整段（必须含 z_c0=），
   存成一行文本 /mnt/us/zhihu/cookie.txt，
   再回「账号 / 登录」点「导入 Cookie」，屏幕会显示校验结果。

   ※ 没有「手机号 + 短信验证码登录」：知乎登录表单由网页 JS 加密
     并带滑块验证，Kindle 纯 C 程序没有 JS 引擎，无法实现。

3) 私信（只读）
   首页 →「私信」→ 会话列表（昵称 / 摘要 / 未读数）
   → 点会话看消息全文，同样是整页翻页；点页眉返回会话列表。
   目前只能看，不能回复（Kindle 没有系统中文输入法）。
   若读不到会话，用 KUAL →「2. 诊断与排障」→「私信端点诊断」
   把各端点的 HTTP 状态显示在屏幕上，再按需改 social.conf。


四、出问题了先看这里
--------------------
KUAL →「知乎阅读」→「诊断和排障」里有七个自查入口，都不需要电脑：

  · 安装 / 更新程序       —— 把程序复制到 /mnt/us/zhihu/
  · 查看运行日志         —— 屏幕上看 log.txt（程序日志）和 run.log
  · 运行自检（不联网）   —— 36 项：签名、JSON、HTML、PNG/WebP、触摸旋转、
                            id 抽取、影子副本、双页高排版、私信端点钉死等
  · 硬件诊断             —— 看屏幕参数、字体、触摸设备、四方向触摸映射自检
  · 诊断：接口           —— 热榜/推荐/正文各打一次，给出真实 URL、状态码、响应体前 200 字节
  · 诊断：私信端点       —— 列出各候选私信端点的状态码
  · 排障：抓 eips 参数   —— 抓系统 eips 的刷新 ioctl（刷新出问题时用）

1) 打开后有界面，但点哪儿都没反应
   1.2.4 之前最常见的原因是「触摸屏被系统界面独占着」——独占
   （EVIOCGRAB）是排他的，别人拿了，我们就收不到任何触摸事件。
   现在会自己判断并写在日志里，看 /mnt/us/zhihu/log.txt：

     input: /dev/input/event8 grab=ok（已独占触摸屏）   -> 正常
     input: /dev/input/event8 grab 失败 errno=16(...)   -> 被系统占着
     app_run: 触摸独占 grip=ok                          -> 正常

   出现 grab 失败时：在 /mnt/us/zhihu/config.txt 里加一行
       framework=stop
   重开程序（这会停掉系统界面来接管触摸；退出时会自动恢复）。
   程序自己也会每 2 秒补抢一次，所以偶尔"过几秒才动"是正常的。

   若显示 0 个设备，则是没读到 /dev/input/event*：
   确认是越狱的 Kindle，并把「硬件诊断」页拍照反馈。

2) 打开后整机重启（黑屏 → 转圈 → 重新开机）
   1.2.3 已修。这次不是程序崩溃，也不是屏幕刷新的锅：
   framework 停掉之后没人再告诉对方电源管理"我在用"，Kindle 到点
   自动挂起；而没有系统界面的情况下唤醒会失败，硬件看门狗于是把
   整机复位。日志里表现为"心跳记到第 3 分钟就断，既没有 exit rc=
   也没有 *** CRASH"，和崩溃完全不是一回事。

   1.2.3 的三手：
     · 不再杀 framework，改成把 cvm 冻结（kill -STOP），
       powerd / lipcd 都活着，退出时 kill -CONT 原地恢复
     · 启动最早阶段就拿内核 wakelock（/sys/power/wake_lock）
     · 防休眠心跳从 30 秒改成 5 秒，失败会记进日志

   验收办法（不用电脑）：打开后**静置 5 分钟以上不碰它**，
   不重启就说明修好了；再翻几页确认屏幕有反应、退出能回系统界面。

   确认办法：看 /mnt/us/zhihu/log.txt 里这几行
     wakelock 已持有：/sys/power/wake_lock   -> 内核锁拿到了
     lipc 防休眠已生效（powerd 应答正常）      -> powerd 也在
     心跳 ... 挂起=0s 刷新=4 eips=12/0        -> 一次没睡、eips 在刷
   刷新那一行的 eink 值：
     eink=1  -> 原生 MXCFB_SEND_UPDATE（最好）
     eink=4  -> 交给系统 eips 刷（KO3 上正常就是 4）
     eink=3  -> 只写内存，屏幕基本不动
     eink=2  -> 老路径 FBIOPAN_DISPLAY，KO3 上会重启

   万一还重启：KUAL →「查看运行日志」会把 suspend 统计和 kmsg.log
   末行一起显示出来；把 log.txt、run.log、kmsg.log 三个文件发出来
   就能定位。详细说明见发布包里的「变更说明-1.2.3.md」。

1.5) 屏幕转过来之后，点击位置不对（只有 0° 那面是准的）
   1.2.5 已修。原因是"显示按旋转转了、触摸没转"——显示走 pix_off()
   的软件旋转，触摸却只在启动时写死了一套 (0,0,0)，所以除 0° 外
   三个方向全错位。
   现在改旋转时会同时改触摸映射（把 pix_off 求逆，不是猜出来的），
   四个方向都准。确认办法：看 log.txt
     app_run: 画布 1680x1264 物理 1264x1680 rot=1 触摸范围 0..1263/0..1679
     app_run: 触摸映射自检 ok
   若某个方向仍然点偏，把这两行发出来（这属于映射算错了，不是校准问题）。

1.6) 用着用着偶尔看见系统桌面（顶栏时钟一闪）
   这是 1.2.4 的共存模式留下的窗口：系统界面（cvm）还在画顶栏，
   而那时的守护是 1 秒抽查一次、发现后重新排版重画，中间能看见桌面。
   1.2.5 改了三处：
     · 每次刷屏后把整页存进一块"影子内存"，被盖掉时直接整页写回
       （毫秒级，不用重排版）
     · 守护从 1 秒一拍改成 120ms 一拍
     · 如果 1 分钟内被抢 8 次以上，程序会请启动脚本把系统界面停掉
       （framework stop），彻底独占屏幕；退出时自动启动回来
   日志里会看到：
     屏幕守护: 像素被别的进程改过，影子回灌 scr=0（累计 3 次）
     屏幕守护: cvm 持续抢屏 8 次，已请求启动器停掉系统界面
   想一进门就完全独占，可以在 config.txt 写 framework=stop。

1.7) 热榜/推荐能看到标题，点进去 404
   1.2.5 找到真因了：知乎的 id 已经是 19 位（例如
   2103784826771862921），1.2.4 把它当普通数字读，先转成 double
   再转成 long——19 位超出了这两者的精度，读出来变成
   2103784826771863040，差 121，请求的 id 根本不存在，于是 404
   （签名要是坏了会回 403，不会回 404）。在 Kindle 的 32 位 ARM 上
   还会直接溢出成负数被丢掉，变成"空 id"请求。
   1.2.5 改成按原始字面量取 id（不再经过数字转换）。
   另外三处也一起改了：
     · 链接 id 抽不出来时不再"带着空 id 去请求"，直接报
       "这个条目没有可用的 id，打不开"并把原始链接写进日志；
     · 接口改用桌面浏览器的 User-Agent，详情请求带上下文 Referer，
       cookie 里若有 zst_81 会一并透传成 x-zst-81；
     · 详情 404 时自动退到"问题下的回答列表"里按 id 捞正文。
   还是 404 的话：KUAL →「诊断：接口」，屏幕会显示
     hot: rc=0 n=50 status=200
     item0: type=3 id=- qid=1234567890
     detail: rc=-1 status=404
     head: {"error":{"code":...
   把这几行拍下来 + log.txt 里 apitest 开头的几行发出来，就能定位
   是 id 不对、路径不对，还是知乎回了"请升级客户端"。
   另外 config.txt 写 ua=mobile 可以把接口 UA 切回移动端试试。

2.0) 静置几分钟弹「应用程序错误」/ 卡在主页点不动 / 点菜单整屏黑闪
   这是 1.2.3 的遗留问题，1.2.4 已修。

   原因是 1.2.3 为了抢屏，把系统界面（cvm）用 kill -STOP 冻住了：
     · 冻住的 cvm 仍然攥着触摸屏独占（排他的），所以点不动；
     · 冻住的界面会被 framework 当成卡死，3~4 分钟后按进程组
       发 SIGTERM，脚本和程序一起被砍（日志里的 rc=143），
       恢复做到一半 → framework 弹「应用程序错误」。

   1.2.4 改成：先探测能不能拿到触摸独占，再决定要不要动系统界面
     · 拿得到  -> 和系统界面共存，完全不碰 cvm（最安全）
     · 拿不到  -> 用 framework stop 正常停掉（不是 kill -9），
                  退出时干净启动回来
   菜单重画也从"整屏全刷"改成"局部快刷"，点菜单不再黑闪。

   确认办法：log.txt 里应有
     framework=auto -> none（触摸屏没被独占...）
     app_run: 触摸独占 grip=ok
     心跳 ... 触摸=183 点击=4 抢屏=0

3) 打开后闪退回主页
   1.1.0 起会把崩溃原因直接写在屏幕上并停留 25 秒，例如：
       zhihu-reader stopped, code 139
       signal 11 - program crashed
       *** CRASH sig=11 SIGSEGV addr=0x0 pc=... lr=...
   拍下这一屏即可定位。code 137 表示被系统强杀（多半内存不足）。

4) 中文显示成方框
   系统里没有中文字体。任选一个中文 TTF 复制到
       /mnt/us/zhihu/font.ttf
   再重新打开。

5) 提示 403 / 需要登录
   游客只能看热榜；推荐、私信、收藏夹必须登录。
   按上面「三之二」扫码或导入 Cookie。
   知乎对部分网络出口有风控：扫码时若提示「网络环境存在异常」，
   请改用「导入 Cookie」，或换一个网络后重试。
   换网络、重新登录通常能解决大部分 403。

6) 点进热榜一片空白，或只有一个「（空）」
   1.2.1 已修，现在会把原因写在屏幕上。按显示的内容判断：
     · 域名解析失败 / 网络请求失败  -> WiFi 没连上，或 DNS 不通
     · 知乎返回错误（40352 / 403）  -> 网络出口被风控，换网络或导入 Cookie
     · 未登录…                      -> 到「账号 / 登录」扫码
     · 接口返回 0 条                -> 登录态失效或风控，重新登录
   如果现象是"进去后一闪就没、画面像被系统界面擦掉"，那是 cvm 没退
   干净。1.2.1 的启动脚本会 kill -9 并确认退出；请务必先执行一次
   KUAL 的「安装 / 更新程序」，否则跑的还是旧脚本和旧程序。

7) 屏幕看起来花了 / 系统界面没回来
   程序异常退出时会自己恢复系统界面。万一没恢复，
   长按电源键 20 秒重启；或 SSH 执行 /etc/init.d/framework start

8) 想卸载
   删除 /mnt/us/extensions/zhihureader 和 /mnt/us/zhihu 两个目录即可，
   不会改动系统分区。


五、数据都在哪
--------------
全部在 /mnt/us/zhihu/ 下：
    zhihu        程序本体
    cookie.txt   登录 Cookie（可选，扫码成功后自动写入）
    font.ttf     自定义字体（可选）
    config.txt   设置
    social.conf  私信端点覆盖（可选，端点变了改这个不用重编译）
    cache/       缓存（图片按文章分目录存放在 cache/img/ 下）
    log.txt      程序日志（崩溃记录、心跳、刷新路径、端点诊断）
    run.log      启动器日志（启动/退出/挂起统计/wakelock/cvm 冻结）
    kmsg.log     内核日志尾巴（每 20 秒抄一次，重启后靠它看原因）
    eips_spy.log 排障用（抓 eips 的刷新参数，平时不存在）
    apitest.txt  接口体检结果（KUAL →「2. 诊断与排障」→「接口诊断」生成）
    dmprobe.txt  私信端点诊断结果（同上，「私信端点诊断」生成）
    log.prev.txt 上一份日志（超过 512KB 时轮转，不再直接清空）
    selftest.txt 自检结果
    diag.txt     硬件诊断结果
    qr.out       二维码登录的临时会话状态


六、1.2.13 改了什么
------------------
这一版修 1.2.12 真机反馈的 6 个问题：

① 顶栏时间冒出：压屏从"连续 3 次退避 3 秒"改成"回灌节流 500ms"，
   冒出来的时间/电量最多可见半秒就被压掉。
② 右下角返回键层级化：回答页 → 回答列表 → 热榜/收藏来源 → 主页；
   物理返回键和左滑同样层级化。
③ 私信消息：新增 App 端（api.zhihu.com）私信路由候选（探针 401=
   路由存在），会话自带 url 不再被拼坏；"200 但没有数据"现在计为
   200* 并把响应体写进日志，方便下次定位。
④ 关于页加了 GitHub 仓库地址。
⑤ 修复：点按加载图片显示后画面冻结（状态机停在加载页没恢复，
   所有点击被忽略——1.2.12 起的 bug）。
⑥ 回答列表每条不再重复显示问题标题，改为回答摘要（最多 3 行）
   + 作者赞同；推荐列表显示标题的做法不变。

（历史）1.2.12 改了什么
------------------
① 设置新增「列表样式」开关（第 7 项，作用于推荐列表和回答列表）：
   详细（默认）：问题标题（加粗）→ 回答摘要（固定 2 行）→ 作者赞同
                （浅灰）。行高拉开、留白充足。
   简洁：只显示问题标题 + 作者赞同。行高小、条目密，适合快速划。
   摘要固定最多 2 行截断，行高恒定——翻页不跳。
② 回答条目以问题优先展示：标题位显示问题标题（之前显示的是回答
   摘要），摘要画在标题下面。区分同一问题下的多条回答看摘要。
③ 阅读页标题折行上限 3 行放开到 8 行：长问题标题完整显示。

（历史）1.2.11 改了什么
------------------
这一版修 1.2.10 真机反馈的三个排版问题：

① 文章尾部空白页（主修）
   5 页的文章第 4、5 页全空白；只有 2 页的文章两页全空。
   根因是排版分页数组收尾写错（1.2.9 引入）：页数多算一页、
   最后一页的起点从未赋值。修复后每页都有内容，页数也对了。

② 阅读页标题完整显示
   标题自动折行，最多 3 行（页眉高度跟着行数走），

六点九、1.2.8 改了什么（历史）
------------------
这一版修的是 1.2.7 真机上的三个问题，外加把图片做成三档。

① 各界面文字重叠
   根因不在排版，而在**刷屏方式**。KO3 上驱动不接受 mxcfb 的 SEND_UPDATE，
   程序实际用的是系统自带的 eips；而 `eips -g 图片` 默认是**局部更新**，
   只把"有差异的像素"推上去，**不会把上一屏的黑色擦回白**。
   于是从阅读页退回列表、再回首页，走过的每一屏都留在纸上，越叠越花。
   现在：
     · 换屏（首页 / 列表 / 阅读 / 设置 / 关于 / 账号 / 二维码 / 私信）一律
       发 `eips -f -g`（full update，整屏闪一下，波形 GC16），底是干净的；
     · 只有"翻一页"才走局部更新（不闪），并且每 3 页自动补一次全刷；
     · 顺手修掉另一处"看起来像重叠"的排版问题：页底最后一行会被页脚线
       裁掉，标题孤零零卡在页脚上。现在段落 / 标题排到页底前会整体挪到
       下一页，标题至少带一行正文一起出现。

② 有的界面发虚、字不清楚
   以前一开"快速"，翻页就用电子墨水的 DU（A2）波形。DU 是**二值化**波形：
   只翻像素、不重建灰阶，抗锯齿的灰边被直接量化掉，字就发虚；同时留下
   上一屏的浅灰影子，和①叠在一起。
   现在默认用 GC16 + 局部更新：不闪屏，但波形是"擦干净再写"，灰阶完整。
   想要极速、能接受残影的，可以在 config.txt 手写一行 `du=1`。
   设置页第 2 项改名为「翻页刷屏」，值只有「不闪（局部）」和
   「整屏闪（最干净）」两种，不再暗示"清晰=慢"。

③ 正文图片一直加载不出来
   这是 1.2.7 的一个实打实的 bug：缓存文件名是 <url 的 md5>_<宽>.zhg，
     · 存盘时用的是**解码后的实际宽度**（竖长图会被一页高度压窄，
       比如 1200×2297 解成 679×1300，于是存成 ..._679.zhg）；
     · 查缓存时用的是**固定宽度 1024**（..._1024.zhg）。
   两者对不上，于是"下载成功、解码成功、写盘成功，界面永远查不到"，
   最后统一变成「[图片]（未能加载）」。
   现在文件名固定用 1024 这个键（真实宽高存在文件头里，显示时再缩放），
   并且每次存完立刻按查询键回读一次——再出现同类问题会直接写进日志，
   不会静悄悄地失败。
   注：1.2.7 之前下过的图文件名都是错的，升级后第一次打开文章会重新下
   一遍；想省事可以在设置里「清空缓存」后再读。

④ 「显示图片」改成三档
   设置页第 4 项点一下循环一次：
     关闭     —— 正文里只留一行「[图片]」，最快、最省流量；
     点按加载 —— 图片位置是一个带向下箭头的框，写着「点按加载此图」。
                 点哪张下哪张，下好就地显示；**失败原因会直接显示在屏幕上**
                 （HTTP 403 / 不是 JPEG / 网络超时 等），不用再去翻日志。
     自动加载 —— 文字先出来，图片在后台从正文第一张开始逐张补，
                 补上就替换占位，只刷当前页。
   老配置里的 images=1 会自动落到「点按加载」这一档。

· 自检 33 项 → 34 项（新增 [imod] 三档图片模式：自动档排队、点按档只标记）。
· 新增两个手写项（设置页不显示，写进 config.txt 就生效，改字号也不会被冲掉）：
    eipsclean=0   eips 只做局部刷新（1.2.7 老行为，快但有残影）

六点六、1.2.6 改了什么（历史）
--------------------------------

① 按实体翻页键会闪出 Kindle 原生主页

  缓存、[imgl] 图片不跨页、[date] 时间格式）。
· 已知限制：只解基线 JPEG；渐进式/PNG/WebP 显示占位；首屏带图会慢几秒。

六点七、1.2.5 改了什么（历史）
------------------------------
这一版修三处互相独立的问题，都不是"再改改参数"能好的：

① 翻转后触摸不跟随
   显示用 fb.c 的 pix_off() 按 rotate 做软件旋转；触摸却由 main.c
   在启动时一次性写死 input_set_transform(0,0,0)，设置里改旋转只调
   fb_set_rotate()，从不碰触摸。于是 0° 准、90/180/270 全错。
   改法：新增 input_set_rotate()，把 pix_off 的映射**求逆**（不是猜
   极性），初始化与"设置里切旋转"两处都调用；同时修掉
   input_probe_text() 会把画布几何清零的隐患。
   自检新增 [rot]：四个方向的"物理→逻辑"必须回到原点。

② 偶尔露出系统桌面
   1.2.4 与 cvm 共存，靠"每秒抽查哈希 + 重排版重画"补救，窗口约 1 秒。
   改法：每次刷屏后把可见页抄进 2.1MB 的影子内存；守护改成整页
   memcmp、120ms 一拍，发现被改就**整页回灌**（memcpy + 一次全刷），
   不再重排版；另外 60 秒内被抢 8 次就写 .want_stop，请启动脚本
   framework stop 彻底接管（退出自动恢复）。
   自检新增 [shad]：不误报 / 能发现 / 回灌一致。

③ 点进去 404
   · 真因：知乎的 id 已经是 19 位（2103784826771862921），超出 double
     的精确范围（2^53）也超出 32 位 long。原来 JSON 数字 → atof →
     long，读出来变成 2103784826771863040，请求的 id 不存在 → 404。
     现在 json.c 保留数字原始字面量，id 一律按文本取（json_get_idstr），
     api.c / social.c 全部改用它。
   · ids_from_url 以前"抽不到 id 也改类型"，于是出现"类型=问题、
     qid 空"，调用方退到 /api/v4/answers/（空 id）→ 404（响应体常空）。
     现在先剥 ?#、按"越具体越优先"匹配、抽不到就什么都不改；
     打开条目时对空 id 直接报错并打印原始链接。
   · 接口改用桌面 Chrome UA（desktop=true 的接口配手机 UA 很可疑），
     详情带上下文 Referer、补 Origin/Accept、cookie 有 zst_81 就透传。
   · 详情 404 自动退到"问题回答列表"里按 id 捞正文。
   · 不再拿"失败时 buf 为空"当证据：现在直接记响应体前 200 字节。
   自检新增 [ids]：8 种链接形态。

· 顺手：私信接口 200 但解析不出时，把顶层键与前 200 字节写进日志
  （以前静默换下一个候选，什么都看不到）；日志超过 512KB 改成轮转成
  log.prev.txt（以前直接清空，会把出事前那几行抹掉）；退出页长句
  改成折行（之前被屏幕右边缘切半句）。
· 新增 KUAL →「诊断：接口（热榜/推荐/正文）」与 --apitest。
· 自检 17 项 → 21 项（新增 [id64] 19 位 id、[rot] 四方向触摸、
  [shad] 影子副本、[ids] 链接解析）。

· 1.2.4 的启动探测/退出还原、1.2.3 的 wakelock/kmsg、1.2.2 的方向位、
  1.2.1 的空态页全部保留。

六点八、1.2.4 改了什么（历史）
------------------------------
解决"界面能用但不好用"：静置弹「应用程序错误」、卡在主页点不动、
点菜单整屏黑闪。根因是 1.2.3 用 kill -STOP 冻结 cvm 来抢屏——冻住的
cvm 仍占着触摸独占（点不动），又会被 framework 当成卡死按进程组清场
（弹错）。1.2.4 改成先探测触摸独占再决定是否接管，并让程序自己也会
在退出时还原。

10 项首页菜单、随机缺字修复）

六点十七、1.3.1 改了什么
------------------
这一版修一个真机反馈：

① 回答列表右下角「返回」直接回主页、跳过热榜列表。根因是
   网络任务结束时界面状态停在"加载页"，导致进入回答列表前
   压层级栈的守卫拒绝入栈——1.2.13 的层级返回在这条真实
   链路上从未生效（自检手动设了状态绕过了这条链）。现在
   任务成功后统一把状态放回任务前的界面，[nav] 自检补两条
   钉子防止回归。物理返回键、左滑、页脚按钮三条路都修好。

六点十八、1.3.2 改了什么
------------------
1.3.1 的层级返回修复没修干净，这版换正确的修法：

① 恢复界面状态时用的参照是"上一次弹消息前的界面"——没弹过消息
   时它是过期值（往往是主页），所以热榜→回答列表的层级栈还是
   压不进去，返回照样直回主页。现在在进入加载页那一刻把当前
   界面记下来，任务成功恢复到它，压栈必然成功。
② 层级压栈加了日志：run.log 里会出现「nav: 压栈 kind=hot …」
   或「nav: push 被拒」，再出问题把 log 发来一眼定位。
